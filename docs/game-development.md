# 新版遊戲開發規範

本文件供後續開發與 Codex 接續工作使用。玩家文案由內容目錄供應；時機、計數、取整與傷害欄位留在系統層。

- 技能、裝備、消耗品、狀態、怪物及系統規則：`game/data/source-sheet.json`，2026-09-11 讀取的「拉霸 Battle｜技能與裝備資料」快照。

- 最新對話修正優先於舊版機器人數值。AP 基礎值為 3、無魔力、燃燒獨立分類、食鐵下回合生效。收藏家下注及鎖格均不會自動轉動。
- 這不是即時讀取 Google Sheets。修改試算表後需同步快照與對應效果資料；不可只換文案而不更改效果。

## 戰鬥順序

1. `BATTLE_START`：設定單位、裝備、技能、被動及下一場戰鬥效果。
2. `ROUND_START`：舊 AP 清為 0，取得修正後的 AP 並扣除詛咒卡懲罰；建立新的傷害池、重設本回合計數、套用待生效基礎攻防。取得基礎防禦護甲，再恢復金剛石保留的護甲；執行回合開始效果後，敵方由左至右保存 intent。
3. 拉霸：免費產生 3×3 盤面。鎖定立即花 1 AP；每次重轉花 1 AP，鎖定維持。抽選權重按實際總和正規化，不補差額，每種最低為 1。山羊頭骨保證符號完成後，才判定本次最終九格的裝備效果。
4. 確認盤面：生成八張卡片，合併保留卡與特殊卡。每張三骷髏卡記錄下回合 −1 AP，AP 最低 0。磨菇使用當下直接加牌。
5. 出牌階段：正常出牌與使用技能是不同指令。正常出牌按每張卡處理牌面及出牌事件；技能卡只驗證材料並消耗。可一次選多張，也可多次操作，AP 耗盡不會自動結束玩家回合。
6. 結束回合：先記錄保留前是否空手，再選擇保留卡片並扣 AP。每張 1 AP，沒有額外的三張限制，舊卡可再次付費保留。執行玩家回合結束效果，鎖定最左側存活敵人，結算一次戰鬥傷害。
7. 敵方行動：依左至右執行保存的 intent，選擇最右側存活我方單位。無法行動的單位跳過動作。
8. 全體回合末尾：敵人回合結束效果 → 狀態結算（包含燃燒與食鐵）→ 金剛石記錄剩餘護甲 → 有限持續回合 −1、移除失效狀態 → 夏賜儀碇等最末尾檢查 → 下一回合。

每次傷害後立即判死；死亡事件處理完再判定任一方是否全滅。回合已終止時不繼續通常事件。群體詛咒的所有目標先計算與套用，再共同判死。

## 材料條件

| 寫法 | 判定 |
| --- | --- |
| `Σ⚔️>=3` | 所有材料的有效劍總數至少 3；可使用三張各一劍的卡片 |
| `[🛡️=1]` | 每張投入的卡片各自恰好一個有效盾；可一次投入多張 |
| `[🛡️=3], [✨=3]` | 兩張不同卡片分別滿足一個槽位，不能用一張卡同時填兩槽 |
| `Σ🛡️>=2 & Σ✨>=1` | 同一組材料同時滿足兩項總數條件 |
| `> / >= / = / <= / <` | 大於／以上／等於／以下／小於，必須明寫比較符號 |

🍀可作為⚔️、🛡️、✨的有效符號；要求🍀時只數真正的🍀。不同符號的有效數量獨立判讀，不做不可見的萬用牌扣配額。多卡槽配對使用回溯，避免貪婪配對漏判合法組合。退魔擊明確使用 `printed.star`，不讀取萬用後的✨數量。

## 傷害與事件

- `battle`、`extra`、`burn`、`reflection`、`curse`、`poison` 是六個獨立類型；`hpDamage` 是最後實際扣除生命的數字，不是第七個傷害類型。
- 任何內容使用 `damageType: "battle"` 都先加入傷害池。只有回合結束的 `attack()` 提交戰鬥傷害。新增效果不可繞過此入口直接扣 HP。
- 玩家操作中的 `pool` 加減乘算立即改寫池值，不回溯。例如 `(3+12)×2=30` 與 `3×2+12=18`。
- 同一時點的事件先加算再乘算；同類優先技能再裝備，來源內按取得順序及定義順序處理。玩家已分開操作的先後順序不可重新排序。
- 一張卡的多個額外傷害來源分開處理，不合併；每個獨立事件都可重新取得最左側存活敵人。一次技能或消耗品已鎖定的目標死亡時，不把同次效果轉移給下一隻；使用者自己的代價仍照常支付。
- `Hook.forEachCard` 可查詢本回合出牌紀錄並逐張觸發。需要每張卡取得獨立目標時設定 `targeting: "perCard"`；該張卡內的傷害及附加狀態仍共用目標。
- 十字弓的無視護甲部分記在同一傷害事件的 `bypass`，會受整次攻擊倍率影響，仍接受適用的百分比及固定減傷。
- 血蛭接在 `battleHit`：確認攻擊成立、減傷前數字大於 0 時恢復生命。攻擊被先行額外傷害取消時不恢復；被護甲完全擋下仍恢復。
- 元素瓶在既有有效額外傷害減傷前數字 `>1` 時 +1；燃焰之劍在該事件後加燃燒。它們不要求生命傷害，元素瓶也不建立新傷害事件。
- 每種傷害的減傷順序定義於 `rules.damage[type].pipeline`。目前一般管線為護甲 → 百分比 → 固定 → 特殊；反射專屬減免先處理，再扣護甲。詛咒不扣護甲。所有類別均保留各計算欄位及有序 `steps`。
- 數值取整使用四捨五入。燃燒 5 層結算後成為 3 層；1 層結算後直接清除，避免永久停在 1 層。隨機整數、陣列索引使用 `floor`，不屬於傷害取整。
- 攻擊力 +3／+5／+7／+9 是不同狀態；相同 ID 不疊加，以最後一次施加的持續時間刷新。持續時間由技能、裝備或事件提供，不寫死在狀態疊加規則中。

## 新增內容

先組合現有 `Effect`、`Hook`、`Modifier`。例如新增一個消耗總計兩星、提供戰鬥傷害的技能，只需在技能資料加入：

```ts
{
  condition: "Σ✨>=2",
  description: "對敵人造成 8 點戰鬥傷害。",
  effects: [{ op: "damage", damageType: "battle", target: "target", amount: 8 }],
}
```

新增一個「每張正常出牌造成 2 點額外傷害」的裝備，使用 `cardPlayed` 搭配 `damage`；技能材料走 `cardUsed`，不能誤掛到出牌事件。

全新機制才新增處理器；不要在主回合函式或 UI 裡加入技能／裝備 ID 分支。奇遇使用 `eventEffects[type]`，不同奇遇共用治療、獲得獎勵、進入戰鬥等處理器。獨立目標、群體目標及死亡時效果有回歸測試作範例。

## 探索與保存

普通冒險起始攜帶規則、技能欄位上限、地區強度、事件機率、掉落與商店價格均在 `game/data/adventure.ts`。保留手牌上限與技能欄位上限是兩回事。

戰鬥結束後才領取戰利品並前往下一節點，保留剩餘生命、最大生命、裝備、技能與消耗品。戰鬥狀態、手牌及傷害池不直接帶入新戰鬥；下一場封印或祝福由專用待生效欄位轉交。Boss 勝利恢復生命並增加地區深度。

收藏家總計允許四次實際轉動；下注保持 0 次，鎖格只改變 `lockedIndex`。每次只在玩家按下轉動後抽選，第四次仍未成功才失去賭注。

目前使用瀏覽器本機續玩；保存起始種子與所有已成功的指令，重新開啟時重播驗證。拒絕的指令不扣資源、不改 RNG、不寫入紀錄。存檔以 `revision` 管控相容性；更動會影響重播的規則時，必須升版或提供明確遷移。

Google Apps Script 玩家帳號、跨裝置存檔與 Discord 互動層尚未接入。本機存檔不是伺服器認證或防作弊機制；不要把使用者可修改的本機數值直接用於未來公開排行榜。

中毒、毒素傷害與再生仍保留草案，不自創效果。秘法獵犬與岩甲蜥蜴依試算表標示保留在戰鬥測試配置，正常探索不抽到草案怪物。

## 直式戰鬥介面

畫面採手機直式：上方戰場保持玩家在左、敵人在右，下方依拉霸／出牌／保留階段切換操作。生命、護甲、待結算戰鬥傷害與 AP 固定顯示；背包及紀錄使用獨立面板，出牌與回合結束按鈕固定在操作區底部，手牌區獨立捲動。

`components/battle/presentation.ts` 管理場景、角色圖與外觀映射，新增角色圖不需改動戰鬥引擎。守衛類共用石像素材並區分色調／尺寸。插畫是本次介面素材，並不代表已確認最終美術設定。

每次實際傷害保留不可變的 `DamageRecord.scene` 生命／護甲快照，僅供呈現。`useBattlePlayback` 依提交完成的傷害紀錄播放攻擊、受擊和飄字，期間暫停操作；引擎不等待動畫、不讀取 DOM、不依畫面重算傷害。額外傷害各自播放，只有標示相同 `batchId` 的原子效果（例如詛咒）一起呈現。減少動態偏好會直接呈現結算結果。

## 開場、奇遇與結算介面

| 元件 | 責任 |
| --- | --- |
| `AdventureSetup` | 開場插畫、起始技能／裝備選擇、固定在底部的開始按鈕 |
| `components/ui/Modal` | 原生 dialog、焦點管理、背景隔離、可選擇的關閉／Escape 行為 |
| `SlotBoard` + `BattleView` | 拉霸 Modal，顯示 AP、鎖定、重轉、確認盤面 |
| `AdventurePanel` | 依奇遇階段顯示文字、選項、交易、鍛造與收藏家操作 |
| `EncounterArt` | 奇遇 ID 與插畫格位映射；未知事件使用通用遺跡道路圖 |
| `RewardCard` | 共用戰利品、商店與石室獎勵的名稱、稀有度及效果呈現 |
| `RewardModal` | 勝利金幣、戰利品選擇與繼續探索；不在渲染時發獎 |
| `RunEndScreen` | 冒險結束的抵達層數、擊敗數、金幣及重新出發 |

新回合進入拉霸階段時自動開啟 Modal，等前一回合的動畫結束才顯示。關閉或按 Escape 只改變視窗狀態，不確認盤面、不花 AP、不解鎖；玩家可查看敵人與背包，再打開拉霸。按「確認盤面」才送出引擎指令。

勝利動畫完成後顯示「領取戰利品」，再送出 `settleBattle` 並開啟獎勵 Modal。獎勵必須明確選擇一項、放棄或繼續，不能點背景略過；金幣只依引擎狀態顯示，不因視窗重新掛載或重新載入而重複領取。敗北／雙方全滅則進入冒險結束畫面。

奇遇使用 3×4 共用插畫集；11 張對應既有事件，1 張作通用場景。圖像、玩家文字與結果處理器分開維護。缺少金幣或物品的選項會停用並顯示原因，所有分支仍透過既有 `AdventureCommand` 驗證。
